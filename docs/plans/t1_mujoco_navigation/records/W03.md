## 故障分析与决策

1. 首次 Git add/commit 因工具沙箱把 .git 设为只读而失败（exit 128）；按用户明确 Git 授权使用审查通过的提权 Git 操作，未 reset/clean/push，也未暂存用户文件。
2. 首次 /tmp `ros2 run` 进程 exit 0，但沙箱禁止本地接口/UDP，DDS 报 getifaddrs/Error creating socket: Operation not permitted。这次**不计为完整验收通过**；原始日志 ros2-run-initial.txt。已获工具审查允许本地 sockets 后，真实 run/launch 均无该错误、exit 0。没有替换 RMW 或升级环境。
3. 新增安装模块一致性检查时，验收脚本在仿真 venv 内执行纯 ROS launch_support 导入，缺少 apt lark 导致 exit 1。系统 /usr/bin/python3 中 lark 1.1.9 来自 /usr/lib/python3/dist-packages；ros2 CLI/launch 一直采用系统解释器且已经成功。修复为 importlib.util.find_spec 文件定位比较，不执行 launch 模块；verification-c4-failed-installed-import.json 保留失败摘要，最终 C4 重验 13/13 PASS。没有安装 lark、复制 site-packages 或重装依赖。

解释器选择依据：系统 Python 3.12.3、rclpy、NumPy 1.26.4、colcon/pytest 可用，缺 MuJoCo/torch；venv Python 3.12.3、rclpy、NumPy 2.5.4、MuJoCo 3.15.0、torch 2.14.1+cu130 可用，缺 colcon/pytest。系统 colcon 与生成 console script shebang 都是 /usr/bin/python3。公共 t1_diagnostic Bash 包装执行 $T1_VENV/bin/python -m t1_mujoco.diagnostic，显式固定解释器、传递信号/退出码；内部 t1_diagnostic_python 不是公开运行入口。纯 ROS launch 保留系统 Python。未污染全局 PYTHONPATH 或 .bashrc。

上游 booster_deploy 无 setup.py/setup.cfg/pyproject.toml，只有 requirements.txt；没有 pip install -e。仿真进程内只按 upstream_path 插入 sys.path、导入 tasks.locomotion.robots.t1、deepcopy 注册配置；实测修改副本不会改变注册表，任务注册只有 t1_walk。资产来自已安装 booster_assets，额外 assets_path 必须一致。代码无硬编码用户名。此为 W03 范围内选择，不改变 W02 架构或接口语义，无需跨步骤 ADR。
